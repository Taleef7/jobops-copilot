# Fully-pinned build constraints for the agent Docker image (reproducible builds — #168).
#
# Generated from a real image build's `pip freeze`, so `docker build` resolves the EXACT
# same versions every time (the ranged requirements*.txt stay loose for dev ergonomics;
# this file is applied only in the Dockerfile via `pip install -c constraints.txt`).
#
# torch is the CPU wheel (torch==...+cpu) from https://download.pytorch.org/whl/cpu.
#
# To regenerate after a deliberate dependency bump, resolve the RANGED requirements
# UNCONSTRAINED (building the image applies THIS file, which would just lock the old pins
# back in), then freeze:
#   docker run --rm -v "$PWD/services/agent:/a" -w /a \
#     python:3.12-slim sh -c 'pip install -q -r requirements.txt \
#       && pip install -q --index-url https://download.pytorch.org/whl/cpu torch \
#       && pip install -q -r requirements-rag.txt \
#       && pip install -q --upgrade setuptools && pip freeze' \
#     > services/agent/constraints.txt
#   then re-add this header and update the torch/setuptools pins in the Dockerfile.
#
# Security bumps can also be made by hand, each to the lowest fixed version: then check the
# whole set still resolves to exactly these pins for linux / cp312 (pip --dry-run with
# --platform, or `uv pip compile --python-platform x86_64-manylinux_2_28`). The 2026-10-29
# bumps (filelock, langgraph*, OpenTelemetry with azure-monitor, setuptools) were made so.
